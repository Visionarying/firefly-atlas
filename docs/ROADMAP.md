## 二、参考项目与我们的定位

### 参考过的项目

| 项目 | 与本项目的关系 |
| --- | --- |
| `hslr-s/sun-panel` | 原始项目，界面与功能思路的来源；官方已闭源，开源停在 v1.3.0 |
| `mysecret2022/firefly-panel` | 参考项目，sun-panel 的二次开发版（作者 Roland） |
| `glanceapp/glance` | 信息流路线，单二进制 20 MB，widget 生态 |
| `Lissy93/dashy` | 状态检测与主题定制路线 |
| `homarr-labs/homarr` | 纯图形化配置、集成生态路线 |
| `gethomepage/homepage` | YAML 配置 + 服务集成路线 |
| `Garry-QD/FlatNas` | 同技术栈（Vue3 + Go/Gin）的国产导航页 |

### 我们的定位差异

本项目为**独立实现**，未复用上述项目的业务代码。功能与界面的思路有参考，代码从零编写，技术选型主动做了不同取舍：

| 维度 | sun-panel 及其二次开发版 | 本项目 |
| --- | --- | --- |
| SQLite 驱动 | CGO（必须装 gcc 才能编译） | 纯 Go，`CGO_ENABLED=0` 直接交叉编译 |
| 前端嵌入 | go-bindata 生成中间文件 | 原生 `go:embed` |
| 配置方式 | `config/*.yml` 配置文件 | 环境变量，无配置文件 |
| 外部依赖 | 可选 Redis、队列、缓存双实现 | 全部进程内，零外部服务 |
| 初始密码 | 固定弱密码 | 启动时随机生成，日志打印一次 |

**结论**：不在功能数量上与对方竞争，保持"轻、少依赖、易部署"的结构性优势。

## 三、功能取舍的三条原则

1. **只做导航该做的事。** 面板的职责是"把入口摆好、把状态告诉你"，不是替代监控系统、下载器或媒体服务器。
2. **能用一套通用机制解决，就不写 N 个专用适配。** 与其维护 80 个服务集成，不如提供一个"自定义数据源"能力，让用户自己接。
3. **安全默认。** 默认设置应该是安全的，方便是可选开启的（例如验证码默认关、Docker 权限默认不申请）。

## 四、v1.2「Lumen」

目标：让面板**装得下更多内容**，同时补齐图库与导入的短板。

### 4.1 多页面与分栏（核心功能）

**解决什么问题**：现在只有一页，卡片超过 50 张后，分组纵向堆叠会越拉越长，找东西变慢。

**做成什么样**：

- 顶部增加页面标签，例如「主页 / 工作 / 影音」，点击切换
- 每个页面独立拥有自己的分组和卡片
- 每页可选 1 / 2 / 3 列排布，分组按列摆放（原先是一列往下堆）
- 页面本身支持增删改和拖拽排序
- 手机上自动塌成单列

**数据模型**：

```
新增表 item_icon_pages
  id, user_id, title, sort, columns, created_at, updated_at

改造表 item_icon_groups
  新增字段 page_id（指向所属页面）
```

**迁移策略（关键风险点）**：

1. 启动时检查：是否存在 `page_id = 0` 的分组
2. 若存在，创建一个名为「我的主页」的默认页，把所有旧分组归属过去
3. **迁移前自动复制一份 `database.db.bak`**，失败可人工回退
4. 迁移只执行一次，用系统设置项打标记，避免重复迁移

**备份兼容规则**：

| 场景 | 处理 |
| --- | --- |
| 导入 v1.1 的 JSON 备份（无 pages 字段） | 全部归入「默认页」，正常显示 |
| 导入 v1.2 的 JSON 备份 | 按 pages 还原 |
| 整站 ZIP 备份 | 同上，manifest 里增加 pages 段 |

**验收标准**：

- 老数据库升级后，原有分组与卡片数量、顺序完全不变
- v1.1 导出的备份能被 v1.2 正确导入
- 三种列数在桌面和手机上都正常

### 4.2 图库缩略图持久化与压缩

**解决什么问题**：现在图库列表直接加载原图，一张 3 MB 壁纸会让列表加载很慢，NAS 上尤其明显。

**做什么**：

- 上传时自动生成缩略图（长边 320 px），存到 `uploads/thumbs/`
- 图库列表只加载缩略图，点开看大图时才加载原图
- 支持选中多张后批量压缩（转 WebP，质量 82）
- **SVG 与 GIF 跳过处理**，避免破坏矢量与动画

**压缩的安全边界**：压缩会覆盖原文件，属于不可逆操作。方案是先复制一份到 `uploads/originals/`，UI 上明确提示"原图已保留，可手动删除"。待开发时再定是否要保留。

### 4.3 书签增量导入

**解决什么问题**：现在每次导入书签都会新建同名分组，重复导入会产生大量重复分组和重复卡片。

**做什么**：

- 同名分组自动复用，不再重复创建
- 已存在的网址可选「跳过」或「更新标题」
- 导入结果分类显示：新增 N 个 / 更新 N 个 / 跳过 N 个

### 4.4 四项小改进

| 功能 | 说明 | 参考来源 |
| --- | --- | --- |
| 数字快捷键 | 按 `0`–`9` 直接打开对应位置的卡片 | Dashy |
| 搜索前缀跳转 | 输入 `!g 关键词` 直接走 Google，`!b` 走百度 | Dashy |
| 版本更新提示 | 设置页显示"有新版可用"，读取 GitHub Release | FlatNas |
| 弹窗双击最大化 | 双击标题栏全屏 / 还原，并加毛玻璃背景 | Roland 二次开发版 |

## 五、v1.3「Sentinel」

目标：从"能用"走向"能看出问题"。

### 5.1 服务状态历史与告警

- 每 5 分钟采样一次每张卡片的在线状态，写入历史表
- 新增「服务状态」页：24 小时在线率、最近延迟、最后检查时间
- **状态变化才提醒**（在线→离线提醒一次），避免每 60 秒刷屏
- 历史数据保留 7 天后自动清理

技术要点：新增 `health_samples` 表；采样由后台 goroutine 驱动；在线率用 SQL 聚合，避免全量读内存。

### 5.2 自定义小组件（待开发转正）

**做什么**：新增一种卡片类型「数据卡片」，配置三样东西：

1. 数据地址（返回 JSON 的 URL，可带请求头）
2. 取值路径（比如 `data.downloads.length`）
3. 显示模板（比如 `下载中：{value} 个`）

**为什么不做 80 个集成**：每个专用集成都要跟随对方 API 变更维护。一个通用取数能力可以覆盖大部分需求，且不增加维护负担。

**安全边界**：只取数和文本替换，**不执行用户提供的 JavaScript**。

### 5.3 其它三项

| 功能 | 说明 |
| --- | --- |
| 磁盘挂载点多选 | 系统监控可从"只看数据目录所在盘"改为可选任意磁盘 |
| 关于页与免责声明 | 开源项目对外发布的常规配置 |
| 登录验证码（可选开关） | 默认关闭，管理员可开启，用于公网暴露场景 |

## 六、v1.4「Bilingual」

- 中英双语，界面文案抽成语言包
- 词条结构可参考 Roland 二次开发版的 213 条中英对照，减少翻译决策成本
- 语言可切换并记忆，默认跟随浏览器

**为什么单独成一个版本**：i18n 会改动登录页、首页、设置弹窗、卡片编辑、云存储、备份等几乎每个组件，落地面很大。与数据结构改动放在同一版本，出问题时无法判断是哪一类改动引起的。

## 七、明确不做的功能

| 功能 | 不做的理由 |
| --- | --- |
| Docker 容器管理 | 需要挂载 `/var/run/docker.sock`，等于把宿主机 root 权限交给面板；本项目有普通用户角色，风险高于同类单用户面板 |
| 子路径部署（`/panel/`） | 当前只使用根路径。需要时再改，成本约半天，改动面是 `vite base` 与 Go 路由前缀 |
| 上百个服务深度集成 | 维护成本会压过一切收益，改用「自定义小组件」覆盖 |
| 自由画布（绝对定位拖拉） | 移动端适配会变成长期填坑，现有分组 + 列布局已够用 |
| RSS / 天气 / 热榜 / 音乐 组件包 | 会把"导航面板"变成"信息聚合页"，与定位冲突，包体与维护面都会涨 |
| 邀请码 | 参考项目里属于残留代码，无实际用途 |

## 八、发布前必须处理的合规与品牌问题

这一节与功能无关，但影响项目能否被正常使用和传播。

### 8.1 缺少 LICENSE 文件（必须补）

当前仓库没有 `LICENSE`。没有许可证的开源项目，在法律上默认"保留所有权利"，别人**不能合法使用、修改或分发**，也不能提交贡献。

建议采用 **MIT 协议**：与参考项目一致，兼容性最好，商用与二次开发都不受限。

### 8.2 关于页文案与事实不符（必须改）

现在设置弹窗的「开源与致谢」写的是：

> 本项目基于 hslr-s/sun-panel 的 MIT 许可进行二次开发与架构重构，保留原作者版权与署名。维护者：Roland。

这句话有三个问题：

1. **"二次开发"不准确**：本项目是独立实现，并未复用代码
2. **"维护者：Roland"错误**：Roland 是参考项目的作者，不是本项目的维护者，会让使用者误解
3. **缺失致谢对象**：没有说明参考了界面与思路

建议改为：

> 本项目的界面布局与功能思路参考了 [hslr-s/sun-panel](https://github.com/hslr-s/sun-panel)（作者：红烧猎人）及其二次开发版（作者：Roland），代码为独立实现。感谢原作者的开源工作。

### 8.3 README 增加致谢段

在 README 末尾增加「致谢与参考」小节，说明三个来源：sun-panel、Roland 的二次开发版、以及借鉴过思路的 Glance / Dashy / Homarr / Homepage / FlatNas。

## 九、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 数据库迁移出错 | 分组与卡片丢失 | 迁移前自动备份数据库文件；迁移脚本可重复执行 |
| 备份格式不兼容 | 老用户导入失败 | 导入时按有无 `pages` 字段分支处理，写兼容测试 |
| 拖拽跨页重构 | 排序功能回归 | 保留原有组内排序接口，跨页只新增接口，不改旧接口 |
| v1.2 范围过大 | 验收周期长 | 功能可逐个验收，任一功能出问题可单独回滚显示入口 |

## 附录：术语速查

| 术语 | 通俗解释 |
| --- | --- |
| 迁移（migration） | 程序升级时，把老数据库的结构改成新结构，保证老数据还能用 |
| 幂等 | 同一个操作执行一次和执行多次，结果一样；迁移脚本必须幂等 |
| 缩略图 | 原图缩小后的预览图，加载快，点开才看原图 |
| 分栏 | 页面内容分成 2 或 3 列并排，而不是一列往下排 |
| i18n | internationalization 的缩写，指多语言支持 |
| CGO | Go 调用 C 代码的能力，开启后编译需要 gcc，交叉编译变复杂 |
| GHCR | GitHub 提供的容器镜像仓库 |
| goroutine | Go 里轻量的并发任务，可以理解为"后台小线程" |
