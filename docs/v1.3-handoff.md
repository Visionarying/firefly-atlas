## 五、v1.3.0「Sentinel」范围

目标：从“能用”走到“能看出问题”。

### 第一阶段（优先）

- 每 5 分钟采样一次卡片在线状态
- 新增 `health_samples` 表
- 记录 `item_id`、`online`、`status`、`latency_ms`、`checked_at`
- 新增「服务状态」页：24 小时在线率、最近延迟、最后检查时间
- 在线 → 离线时提醒一次，避免每 60 秒刷屏
- 浏览器通知作为默认通道
- 维护窗口：维护期间不告警
- 历史数据保留 7 天后清理
- 状态采样由后台 goroutine 驱动，SQL 聚合，不把全量历史读进内存

### 后续小版本

- `1.3.1`：自定义小组件（GET 取数、JSON 路径、模板显示、SSRF 防护、超时/响应体限制、管理员可用、TTL 缓存）
- `1.3.2`：磁盘挂载点多选、可选登录验证码、关于页与免责声明

## 八、v1.3.0 开发进度（2026-11-06）

- 分支：`feat/v1.3-sentinel`，尚未合并、尚未推送
- 版本号已改为 `1.3.0`：`service/global/global.go`、`web/package.json`、`web/src/components/SettingsModal.vue`
- 线上 `3002` 仍是 v1.2.2，没有重启，也没有对真实数据执行新迁移
- 迁移前备份：`data/database.db.pre-v1.3-20261106-230422`

### 已完成

- 新增 `health_samples` 表：`item_id`、`online`、`status`、`latency_ms`、`checked_at`（Unix 毫秒）、`alert`
- 后台 goroutine 每 5 分钟采样，启动 10 秒后先跑一次；并发 6，单目标超时 10 秒
- 采样优先使用 `lan_url`，失败再尝试 `url`；未新增 `health_url` 字段
- 24 小时在线率、最近延迟、最后检查时间由 SQL `GROUP BY` 聚合，只返回每张卡片一行
- 在线 → 离线时写入 `alert=true`；同一采样只提醒一次；维护窗口内不置 `alert`
- 浏览器通知：页面打开时每 60 秒拉取状态，用 `localStorage` 记录已提醒的 `checked_at`
- 维护窗口支持跨午夜（如 `23:30` - `01:30`），按服务器本地时间计算
- 7 天历史自动清理；删除卡片/分组时同步清理样本
- 新增接口：
  - `GET /api/v1/system/health/overview`（登录用户，只返回自己的卡片）
  - `POST /api/v1/system/health/run`（管理员，后台立即采样）
- 设置项：`health_monitor_enabled`、`maintenance_enabled`、`maintenance_start`、`maintenance_end`
- 前端新增「服务状态」面板（系统设置 → 服务状态），首页右上角也提供入口
- 卡片可单独开启/停止监测；可筛选「全部 / 仅监测」

### 验证

- `gofmt`、`go vet ./...`、`go test ./...`、`npx vue-tsc --noEmit` 全部通过
- 临时实例 `DATA_DIR` 为数据库副本，端口 `3013`，未触碰线上
- 实测：首次采样、手动采样、在线率聚合（100% / 50% / 25%）、离线告警、维护窗口抑制告警、8 天前样本清理
- 非管理员调用 `/health/run` 返回 403；未登录返回 401
- 浏览器实测：状态页数据、入口按钮、开启监测即时生效
